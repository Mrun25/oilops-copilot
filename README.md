# Ops Co-Pilot (Hack Day prototype)

Agentic co-pilot for oil-field operations: chat UI over wells / sensor /
maintenance data. The agent calls read-only tools over a local SQLite db
and answers with generative UI - it picks components from a fixed catalog
(table, bar chart, line chart, heatmap, metric) and the app renders them.

## Stack (all free)

- Streamlit + Plotly for the UI
- pandas + SQLite for storage (team's pick; swap later if needed)
- Any OpenAI-compatible free-tier LLM via env vars - defaults to Google
  AI Studio's Gemini free tier (gemini-3.8-flash); Groq and OpenRouter
  free models (Gemma etc.) also work, see `.env.example`
- No key yet? The app runs in offline demo mode (pattern-matched answers)
  so the UI still demos end to end.

## Run it

```bash
pip install -r requirements.txt
python db.py                 # builds data/oilops.db from the CSVs
streamlit run app.py
```

With a key (get a free one from whoever we settle on):

```bash
cp .env.example .env   # fill LLM_API_KEY
export $(grep -v '^#' .env | xargs)   # or source it however you like
streamlit run app.py
```

Terminal-only smoke test: `python cli.py`

## Data

`data/` holds synthetic CSVs generated by `scripts/generate_data.py`
(seeded, deterministic). Schema follows the briefing description:

- `wells.csv` - well_id, block, well_type, status, issue, install_date
- `sensor_readings.csv` - daily pressure, temperature, flow, vibration,
  water cut per well (60 days, 18 wells, 3 blocks)
- `maintenance.csv` - last service, type, next due, technician

The synthetic set includes the cases the briefing called out:
non-producing wells with distinct reasons (pump failure, low reservoir
pressure, high water cut, shut-in maintenance), overdue service records,
and a producing well whose rising vibration precedes flow decline - good
correlation demo.

**When the real organizer data lands:** drop the CSVs into `data/`
keeping these column names (or tweak the SQL in `agent/tools.py`),
rerun `python db.py`, done.

## Layout

- `app.py` - Streamlit chat UI + component renderer
- `agent/core.py` - agent loop (tool calls -> final generative-UI JSON)
- `agent/tools.py` - read-only tools over SQLite + tool schemas
- `agent/prompts.py` - system prompt + UI component catalog
- `agent/llm.py` - OpenAI-compatible client (env-configurable)
- `agent/demo_mode.py` - offline fallback answers
- `db.py` - CSV -> SQLite loader
